# 新手导读

> 这份文档回答三个问题：**从哪开始读**、**一个点击是怎么走完全程的**、**哪些坑我一定会踩**。
> 配合 `docs/CodeConventions.md`（规范）一起看。
> 导航服务 / PageFactory / 生命周期 / 弱事件 / 消息总线的职责，见 [导航架构说明.md](导航架构说明.md)。

## 1. 先跑起来

```powershell
# 在项目目录下
dotnet build
dotnet run
```

- 程序启动后先显示**登录页**（`MainWindowViewModel` 里导航到 `LoginViewModel`）。
- 配置文件：`bin\Debug\net10.0-windows\appsettings.json`（改完重新生成才会复制到输出目录）。
- 日志：**exe 同级的 `Logs\railweld-日期.log`**，永远在这里，不管从哪里启动。
- 数据库：`%LocalAppData%\RailWeldApp\RailWeld.db`。

## 2. 项目地图

| 目录 | 放什么 | 什么时候会改 |
|---|---|---|
| `View/` | XAML 界面（只做布局和绑定） | 改外观 |
| `ViewModel/` | 界面状态、命令、校验 | 改交互逻辑 |
| `Model/` | 普通数据类、配置类、缓存 | 加数据结构 |
| `DataModel/` | 数据库实体 + `DbContext` | 改表结构 |
| `Services/` | 业务与基础设施（PLC、日志、音效、导航） | 加服务 |
| `Interface/` | 服务的接口定义 | 加服务时一起加 |
| `DependencyInjection/` | 所有服务的注册 | 加服务/页面时登记 |
| `Assets/Colors/` | 颜色字典（**唯一的色值来源**） | 改配色 |
| `Styles/` | 全局控件样式；`Styles/Pages/` 放页面专用样式 | 改控件外观 |
| `Themes/` | 复合控件模板（导航按钮、抽屉） | 改复合控件 |
| `docs/` | 本导读、编码规范、旧实现参考 | 写文档 |

两条铁律：

1. **界面不写业务**：`View` 里只放布局与 `{Binding}`，不写 if/循环逻辑。
2. **颜色不写字面量**：XAML 里不出现 `#FF123456`，一律 `{StaticResource XxxBrush}`。

## 3. 建议的阅读顺序

按这个顺序看，每一步都只看一个概念：

| 顺序 | 文件 | 看什么 |
|---|---|---|
| 1 | `App.xaml.cs` | 程序怎么启动：建容器 → 开窗口 |
| 2 | `DependencyInjection/ServiceCollectionExtensions.cs` | 有哪些服务、什么时候单例/瞬时 |
| 3 | `View/MainWindow.xaml.cs` | 窗口怎么把内容交给 `ViewHost`（ContentControl） |
| 4 | `Themes/ViewTemplates.xaml` | ViewModel → View 的 DataTemplate 映射 |
| 5 | `ViewModel/NavigationService.cs` | 导航其实就是"换一个 ViewModel" |
| 6 | `ViewModel/LoginViewModel.cs` | 一个完整页面的写法：字段 → 属性 → 命令 |
| 7 | `View/LoginView.xaml` | XAML 怎么绑定到上面的属性 |
| 8 | `ViewModel/AdminViewModel.cs` | 稍微复杂一点：菜单高亮 + 两层导航 |

## 4. 一个点击的完整旅程

以"在登录页输入账号密码，点【登录】"为例：

```
① 用户点按钮
      ↓  XAML: <Button Command="{Binding SignInCommand}"/>
② WPF 执行命令 → LoginViewModel.SignInAsync()
      ↓  ① 前端校验（ValidateAllProperties）
      ↓  ② VerifyCredentialsAsync(...)   ← 认证后端在这里接
③ 登录成功：_navigationService.NavigateTo<AdminViewModel>()
      ↓  把 NavigationService.CurrentView 换成新 ViewModel，触发属性变更
④ MainWindowViewModel.CurrentView 更新 → ViewHost.Content 变成新 VM
      ↓
⑤ WPF 在 ViewTemplates.xaml 里找 DataType 匹配的 DataTemplate，
      ↓  自动创建对应的 View，并把它的 DataContext 设成这个 VM
⑥ ViewHost 渲染新页面 → 界面切换完成
```

**记住这句话就够了**：导航 = 换一个 ViewModel，界面 = 这个 ViewModel 的 DataContext 渲染结果。
View 不认识 Service，ViewModel 也不认识 View，它们只靠绑定和接口连接。

## 5. 三处"看起来像魔法"的地方

### 5.1 `[ObservableProperty]` —— 自动生成属性

你写的：

```csharp
[ObservableProperty]
private string _userName = string.Empty;
```

编译后等价于（简化版）：

```csharp
public string UserName
{
    get => _userName;
    set
    {
        if (_userName == value) return;
        _userName = value;
        OnPropertyChanged(nameof(UserName));   // 界面才知道要刷新
    }
}
```

所以：**只写字段，不写属性**；字段名必须带 `_`，生成出来的属性名会去掉下划线并首字母大写。

### 5.2 `[RelayCommand]` —— 自动生成 ICommand

```csharp
[RelayCommand(CanExecute = nameof(CanSignIn))]
private async Task SignInAsync(CancellationToken token) { ... }
```

编译后生成一个叫 `SignInCommand` 的 `IAsyncRelayCommand`：

- 方法名去掉 `Async` + 加 `Command` 后缀 → 这就是 XAML 里绑定 `{Binding SignInCommand}` 的来源；
- `CanExecute` 返回 false 时按钮自动变灰；
- 异步命令执行期间**自动不可重入**，不用自己加锁。

### 5.3 构造函数注入 —— 你要什么，容器给什么

```csharp
public LoginViewModel(INavigationService navigationService, ISoundService soundService) { ... }
```

你没有写 `new LoginViewModel(...)`，是 DI 容器在 `NavigateTo<LoginViewModel>()` 时
按构造函数参数自动把已注册的服务传进来。**想用什么服务，就在构造函数里声明**。

## 6. 新增一个页面（6 步）

1. `ViewModel/AdminXxxViewModel.cs`：继承 `PageViewModel`，写属性与命令；
2. `View/AdminXxxView.xaml`：`UserControl`，根元素不写死 `Width/Height`；
3. `Themes/ViewTemplates.xaml`：补一行 `DataTemplate`（VM → View）；
4. `DependencyInjection/ServiceCollectionExtensions.cs`：只注册 `AdminXxxViewModel` 为 `Transient`（View 由 DataTemplate 创建，不进 DI）；
5. `Enum/PageName.cs`：加一个枚举值；
6. `AdminViewModel`：加一个 `NavigationToAdminXxxCommand`（一行），以及 `IsActiveAdminXxx` 高亮属性（一行）；
7. `View/AdminView.xaml`：在顶部导航加一个 `NavigationButton`，绑定上面两个成员；
8. （可选）页面需要在进入/离开时加载/取消，实现 `INavigationAware`；带参数跳转用 `NavigateTo<T>(vm => ...)`。

> `ViewTemplates.xaml` 里写的是显式类型映射，不再依赖"类名必须成对"的命名约定；漏了模板会显示空白，补上即可。

## 7. 新手最容易踩的 6 个坑

| 坑 | 现象 | 解决办法 |
|---|---|---|
| 绑定名写错 | 界面空白，**不报错也不崩溃** | 绑定诊断默认关闭（见 `App.xaml.cs` 的 `PresentationTraceSources`），排查时改成 `SourceLevels.Warning` 再看输出 |
| `{StaticResource}` 找不到 | 启动直接抛异常 | 检查颜色键名；新增色值必须加到 `Assets/Colors/Primitives.xaml` |
| 用了 `DropShadowEffect` / `BlurEffect` | 界面卡顿，远程桌面下更明显 | 禁用；用描边、底色、径向渐变代替（实测差 30 倍） |
| 页面 VM 里直接用 `+=` 订阅单例事件 | 切页后旧 VM 不被释放，内存和回调都越来越多 | 用 `PageViewModel.SubscribeWeak(...)`（弱事件，免退订）；如果页面还持有 Timer/CTS 等非事件资源，再实现 `IDisposable` 并在导航切换时释放 |
| 后台线程里改 `ObservableCollection` | 抛跨线程异常（标量属性 WPF 会自动封送） | 集合更新用 `Dispatcher` 或 `BindingOperations.EnableCollectionSynchronization` |
| 找不到日志 | 以为没写日志 | 日志固定写在 **exe 同级 `Logs\`**；相对路径会跟着工作目录跑，所以代码里用了绝对路径 |

- [ ] `dotnet build` 0 警告 0 错误
- [ ] 跑一次程序，目标页面能正常显示、点击有反应
- [ ] `Logs\railweld-*.log` 里没有新的 `[绑定]` 告警
- [ ] 新加的界面没有十六进制色值、没有 Effect
- [ ] 新加的服务已注册 DI、有接口
- [ ] 单例事件用弱事件或已退订；集合更新在 UI 线程

## 9. 术语表

| 术语 | 一句话解释 |
|---|---|
| **DI（依赖注入）** | 类不自己 `new` 依赖，而是在构造函数里声明，由容器递进来 |
| **MVVM** | View（界面）/ ViewModel（状态与命令）/ Model（数据）三层分离 |
| **绑定（Binding）** | XAML 用 `{Binding UserName}` 从 `DataContext` 上取值，属性变化会自动刷新 |
| **DataContext** | 每个 WPF 元素都有一个，是绑定的"默认数据源" |
| **ICommand** | 界面按钮的执行入口；`CanExecute` 控制按钮是否可点 |
| **ObservableObject** | MVVM 工具库提供的基类，带 `PropertyChanged` 通知 |
| **ObservableValidator** | 在上面基础上加了数据校验（`[Required]` 等特性），本项目所有 ViewModel 的根基类 |
| **Transient / Singleton** | 每次新建 / 全局一个 |
| **async / await** | 异步等待：不阻塞界面线程，写法像同步代码 |
| **`ConfigureAwait(false)`** | 服务层里告诉运行时"不用切回原线程"，避免 UI 线程被抢 |
| **资源字典（ResourceDictionary）** | XAML 里集中存放颜色、样式的地方，`App.xaml` 把它们合并进来 |
| **StaticResource / DynamicResource** | 静态取一次 / 运行时动态解析（本项目颜色统一用静态，快约 5 倍） |
